# Cochonnet Villa

Static Astro site about 15 pet pigs. Two features:

1. **Landing site** — `src/pages/index.astro` rendered from `content/site.json` via `src/render-site.js`. Admin at `/admin/` edits the JSON through GitHub OAuth (Decap CMS, no backend).
2. **3D Villa Map** (`/villa-map/`) — React Three Fiber (Three.js / WebGL) scene, mounted as a client-only Astro React island.

## Commands

- `npm run dev` — local dev server
- `npm run build` — production build
- `npm run preview` — serve the production build (full-speed; dev is slow to first-compile the three/drei bundle)
- `npm test` — Node.js built-in `node:test` runner

## Key patterns

- ES modules everywhere (`"type": "module"`)
- Procedural geometry at runtime; pre-made GLB assets are pigs (`porky-models.js`) and furniture (`furniture-models.js`). Both load through a raw `GLTFLoader` + per-URL promise cache + bbox auto-fit + procedural placeholder/fallback, and mount in R3F via `<primitive object={…}>` — **not** rewritten as JSX, **not** drei `useGLTF` (keeps the framework-agnostic core node-testable and the loader uniform across pigs/props).
- React island only on `/villa-map/` (`client:only="react"` — Three.js needs `window`); the rest of the site stays vanilla Astro static HTML.
- **Version pins (don't bump blindly):** project is on **Astro 6 / Vite 7**. Keep `@astrojs/react@^5` (the v6 line targets Astro 7 / Vite 8) and `overrides: { vite: "^7" }` in package.json. drei `<SoftShadows>` is incompatible with three r184 (broken PCSS depth shader) — avoid; shadows use `PCFShadowMap`.
- Bilingual; content defaults to Chinese (`zh`), `data-i18n` for hooks
- Tests cover HTML render, world geometry, collisions, interactions, porky / furniture / **exterior** / **architecture** placements (incl. that referenced GLB + the colormap atlas exist in `public/`), **blob shadows**, **furniture colliders**, the **beveled villa shell** (`shell.test.mjs` — node-pure build + palette), a **no-overlap regression** (`overlap.test.mjs` — solid non-chair furniture must not clip > 0.5 m²), the **mushroom interior** (`mushroom-interior.test.mjs` — zones/colliders/teleports/factory), its **round-wall containment** (`mushroom-collision.test.mjs` — player-radius-aware radial boundary across all three floors), **curved-wall decor** (`mushroom-wall-decor.test.mjs`), the **real-sky dome asset and unobstructed sightline** (`star-ceiling.test.mjs`), the **dynamic distant sky** (`mushroom-sky.test.mjs` — zero-parallax centring, reveal amount, perceptible asynchronous twinkle, L3 handoff, stencil order, reduced motion and disposal), the **two-state observatory palette/lighting rig and reachable wall switch** (`observatory-lighting.test.mjs`), the React switch state/transition (`observatory-light-switch-react.test.mjs`), and a **same-model spacing guard** (`spacing.test.mjs` — identical props ≥ 1.8 m apart on a floor; chair-family + railing exempt). `npm test` globs `tests/*.test.mjs` (one file per concern), run via the `node --test` runner.
- Impossible Observatory tests additionally cover the adaptation director, Portal/FBO geometry and lifecycle, nebula shader bounds, Gaia v1 provenance/binary/LOD/single-draw contract, automatic quality hysteresis, deterministic diagnostics and the complete React runtime wiring/fallback contract (`observatory-*.test.mjs`). ## Impossible Observatory: runtime, quality and QA

Core implementation is complete; the remaining gate is human visual comfort/wow-factor and target-GPU performance acceptance. The detailed record is `docs/IMPOSSIBLE_OBSERVATORY_PLAN.md`.

**Render architecture:** `MushroomObservatoryRuntime` is the sole browser owner. `PlayerControls` moves the camera at R3F priority `-2`; the runtime updates one shared dark-adaptation state and renders the optional Portal at priority `-1`; R3F then renders the main scene normally. The Portal scene contains **only** the low-frequency volumetric nebula. The 4096×1024 Milky Way backdrop, 360 procedural hero stars and Gaia Points remain in the main scene at native Canvas resolution, all clipped by the physical dome's stencil ref 7. Portal targets have no depth/stencil/mipmaps and hard-cap at 1280×720. HalfFloat framebuffer failure rebuilds as RGBA8; a second FBO failure locks the session to Low. Shader failures are classified: Portal failure removes the volumetric path, Gaia failure keeps the native backdrop/hero stars, and native-sky failure fail-closes to the physical dome. WebGL context loss hides the live layers and restore rebuilds/re-prewarms them.

**Unified switch story:** `observatory-adaptation.js` emits `houseLight`, `roomDarkness`, `portalReveal`, `brightStarReveal`, `scotopicAdaptation`, `nebulaReveal`, `faintStarReveal` and `celestialMotionScale`. `Scene.jsx` lighting/palette/exposure/markers and the sky runtime all read the same `adaptationRef`; do not reintroduce independent component timers. Lights-off drops the room first, begins the Portal after 0.38 s, brings bright stars next and develops faint Gaia/nebula detail over about 10 s. Lights-on recovers in 0.65 s; leaving L3 resets the state. Once the one-shot prewarm is complete, lights-on has zero sustained cosmos draw calls. Reduced motion freezes celestial motion, not the switch fade.

**Gaia v1:** `public/data/gaia-bright-stars-v1.bin` is a 1,920,032-byte, 80,000-row rendering subset produced by `scripts/build-gaia-star-catalog.mjs` from a reproducible Gaia DR3 `gaiadr3.gaia_source` ADQL query. `public/data/gaia-bright-stars-v1.meta.json` stores the query, SHA-256, record layout, completeness caveat and required **ESA/Gaia/DPAC** credit/acknowledgement. The shader uses `uMagnitudeLimit` against each star's Gaia G magnitude, so dark adaptation reveals bright-to-faint catalogue stars in measured order instead of fading the catalogue in as one sheet. The runtime fetches only this local static file; it never queries ESA from the visitor's browser. Keep the `-v1` filename and metadata in sync when regenerating.

| Runtime tier | Gaia | Volumetric Portal | Nebula steps | Native fallbacks |
|---|---:|---|---:|---|
| High | 80,000 | 0.68 scale, max 1280×720 | 48 | 4K backdrop + 360 hero stars |
| Medium | 35,000 | 0.55 scale, max 960×540 | 30 | 4K backdrop + 360 hero stars |
| Low | 8,000 | **disabled; no FBO allocation** | 0 | 4K backdrop + 360 hero stars |
| Minimum | 0 | **disabled; no FBO allocation** | 0 | 4K backdrop + 360 hero stars |

The quality controller uses a rolling p95: two sustained over-budget seconds downgrade one adjacent tier, eight seconds of clear headroom upgrade one tier, and a three-second cooldown prevents thrash. Capability hints cap the highest tier; Minimum is used without WebGL2 or on severely constrained devices. Gaia and Portal allocation begin only near the L2 observatory approach; the decoded 4K texture is uploaded during browser idle time. Native sky/Gaia/composite shaders are first compiled with the default framebuffer active so Three caches the real Canvas colour-space variants, then drawn to a 1×1 target to upload geometry/uniform state before reveal. Low deliberately disables the volumetric FBO; the shipped core deliberately has no Bloom and no temporal accumulation—hero-star SDF flares and an unaccumulated nebula avoid wall wash, ghosting and extra memory.

**Query-only QA harness:** ordinary `/villa-map/` visits always start with lights on and ignore quality/motion overrides. Use these only with `observatory=test` or `observatory=perf`:

- `/villa-map/?observatory=test&view=loft-center&lights=off&quality=medium&motion=full` — deterministic `frameloop="never"`; panel buttons advance 0.5/2/10 s and expose `window.__villaObservatory`.
- `/villa-map/?observatory=perf&view=loft-center&lights=off&quality=medium` — real animation loop, normal `PlayerControls` walking and frame/provider snapshots.
- Views: `l2-stair`, `loft-center`, `loft-edge`, `loft-room`; qualities: `high`, `medium`, `low`, `minimum`; motion: `full`, `reduce`.

The runtime provider reports active tier/p95, adaptation channels, Portal type/size/frame/prewarm/error, Gaia loading/LOD/count/error, 4K texture state and context-loss counters. Baseline screenshots live in `docs/observatory-baseline/`; six implementation-after screenshots live in `docs/observatory-final/`.

**2026-08-02 browser QA checkpoint:** WebGL context loss/restore recovered successfully; 20 light toggles did not increase `renderer.info.memory.textures` or `.geometries`; resizing the browser to 1024×768 produced a 977×658 drawing buffer and 537×362 Medium FBO; lights-on settled at zero cosmos draws. Reduced-motion captures produced identical hashes while full-motion captures differed. The diagnostics browser observed Medium steady-state frame-time p95 around 13–16 ms and High with 80k Gaia plus a 1280×662 FBO. These are browser-harness observations, **not** target-device GPU benchmarks. A fixed 20-second route video and three p95 runs on the target Iris Xe/M1 and UHD 620-class devices remain human acceptance evidence, not code gaps. Phase 6 head tracking, WebXR, WebGPU/TSL and rare celestial events are optional lab work and are not implemented.

## Phase 2: richer assets

The boxy look was an *asset* gap, not a framework one. All six interior rooms now use CC0 GLB furniture (Kenney Furniture Kit — 140 cohesive low-poly pieces, CC0; 25 vendored, ~380 KB) instead of primitives — **72 pieces** across `entry-foyer`, `great-hall-west` (living), `great-hall-east` (dining), `master-bedroom`, `study-loft`, `lounge-balcony`. The villa shell, stairs, partitions, railings, hot springs, mushroom house, terrain and pigs are still procedural. A later "猪窝" cozy-clutter pass piled every room with layered rugs, greenery, books, warm lamps and extra seating (mostly **non-solid** decor so it crowds without trapping the player or tripping the overlap guard; only 2 new solid side-table accents, both in empty corners) and corrected the dining-chair facing (the `chair` model's backrest sits on its -Z side at `rotationY` 0, so seats tuck under the table).

**To add/restyle furniture** (rooms or the courtyard/exterior):
1. Copy GLBs from the kit into `public/models/furniture/` (kit is authored ~0.45× metric; `FURNITURE_BASE_SCALE` ≈ 2.2 lifts it into the villa's metre world — a uniform factor preserves inter-piece proportions, per-piece nudge via `placement.scale`). Upstairs rooms sit at y ≈ 6.66, ground at y ≈ 0.11.
2. Append placement records (world coords) to `furniture-placements.js`; it stamps `footprint`/`floor`/`solid`/`noShadow` on each (footprint from the `FURNITURE_FOOTPRINTS` native-size map × `FURNITURE_BASE_SCALE` × `placement.scale`). Set `solid`/`noShadow` per the model-policy table, or override per record.
3. `npm test` + `npm run build`; eyeball in preview.

**Visual furniture editor (dev-only):** open `/villa-map/?edit=1` to tune positions without blind-coding coords. It swaps the walk controls for orbit + a drag gizmo (drei `OrbitControls` + `TransformControls`), adds a height-adjustable global clipping plane ("dollhouse" cut, `[`/`]` keys) since the roof/ceilings occlude interiors, and lets you click any furniture piece to select it — a panel prints the **paste-ready `furniture-placements.js` record** (Copy button) reflecting the live transform. `G`/`R` toggle translate/rotate, `Esc` deselects. The data file stays the source of truth (tests/overlap guard still gate); you paste the numbers back. Gated on `?edit=1` (`VillaMap.jsx`) so ordinary visitors are unaffected; the editor lives in `react/EditControls.jsx` + the `editMode`/`onSelectPiece` hooks in `Scene.jsx`.

The old per-room `createFurnitureSet` boxes were removed from `assets.js` once every room was migrated.

## Phase 3: grounding, solidity, outdoors

Three streams, conflict-free (each owns new files; only `Scene.jsx` + `world.js` are edited to wire them):

- **Contact shadows** (`shadows.js`) — per-piece soft **blob decals** (flat radial-gradient `PlaneGeometry` + a tiny node-safe `ShaderMaterial`, no texture/canvas), sized to the piece's `footprint`, laid at `position.y + 0.02`, rotated by `rotationY` via a wrapper group. Chosen over drei `<ContactShadows>` (one ground plane can't span two floors + async-loaded GLBs). Tunables in `shadows.js`: `SHADOW_OPACITY` 0.45, `SHADOW_PADDING` 1.35, fragment core `smoothstep(0.5, 0.22, d)` — bumped from softer defaults so the shadow reads beyond an object's base. `noShadow` pieces (rugs, tabletop items) get none.
- **Per-piece colliders** (`furniture-colliders.js`) — solid furniture/props now block the player. Rotated-AABB from `footprint`+`rotationY`, **0.85 shrink** (player radius 0.62 is added at test time, so a full box feels sticky), floor-scoped Y range. Spread into `world.colliders`. Solid set: sofas/beds/tables/bookcases/wardrobe/sideboard/lounge chairs; walk-through: rugs/lamps/books/small plants/dining+desk chairs/coat rack. NB grand-scale furniture means a big piece can fill a small room (the master bed fills the bedroom's north — you walk to its foot, not around it).
- **Exterior props** (`exterior-placements.js` + `public/models/exterior/`) — ~19 courtyard props (fountain/statue ring, lampposts lining the path, benches, planters, flowers, bushes, campfire+logs, rock, sign) from Kenney Nature + Holiday kits, placed in the grassy courtyard (z>0), reusing `createFurniturePiece`. Same stamped shape, so shadows + colliders apply uniformly. Exterior footprint is baked = native × 2.2 × scale (the loader's effective scale).

**Still deferred:** AI text-to-3D for a few signature pieces; richer exterior set; (contact shadows + colliders + courtyard props are now done).

## Phase 5: open meadow · enterable mushroom house · input polish
