# Cochonnet Villa

Static Astro site about 15 pet pigs. Three features:

1. **Landing site** — `src/pages/index.astro` rendered from `content/site.json` via `src/render-site.js`. Edited at `/admin/`.
2. **猪猪小记 blog** — `/notes/` rendered by `src/render-notes.js` (node-pure, build time) from `content/notes.json`. Edited at `/admin/notes/`.
3. **3D Villa Map** (`/villa-map/`) — React Three Fiber (Three.js / WebGL) scene, mounted as a client-only Astro React island.

Both editors are backend-free: they commit through the GitHub Contents API with a fine-grained token kept in localStorage (`cochonnetvilla_github_token`) — no OAuth, no server.

## Commands

- `npm run dev` — local dev server
- `npm run build` — production build
- `npm run preview` — serve the production build (full-speed; dev is slow to first-compile the three/drei bundle)
- `npm test` — Node.js built-in `node:test` runner

## 猪猪小记 blog

**Rendering** — `src/render-notes.js` escapes HTML first, then applies markdown-lite. Emits `/notes/`, `/notes/<slug>/` and the latest-3 landing teaser. `normalizeNotes` sorts newest-first, dedupes slugs, and **preserves the sanitized `image` field** so the editor never strips generated art.

**Publish guard (non-negotiable)** — publish requires known remote state (a successful read *or* a definite 404) and merges remote-only slugs first; a failed initial read must never clobber published notes. A tab that already read successfully keeps its `sha`, so a publish from a stale tab is refused by GitHub with a 409 rather than merged — that 409, not the banner below, is what protects the data.

**Stale-tab banner** (`src/notes-staleness.js`, node-pure) — on `visibilitychange` back to the foreground the editor spends one throttled GET (2 min) to compare its `sha` against the remote and, on a mismatch, offers 「同步最新内容」 → `fetchNotes({ discardLocal: false })`, which merges the remote list *underneath* unpublished local edits (unlike 「重新读取」, which discards them). Fail-soft: a failed request never raises a false alarm.

Two invariants hold here:

- **The banner must not over-promise.** `mergeRemoteNotes` is *local-wins* on same-slug clashes, so syncing a slug both sides edited means the next publish overwrites the other device's version. `findMergeConflicts` (comparing `title`/`date`/`mood`/`body`, never `image`) makes the notice name those entries instead of claiming nothing is lost. A remote *deletion* is deliberately not detected — the editor keeps no record of which local entries came from a past read, so it is indistinguishable from a local draft.
- **One snapshot, judged and merged.** The banner is drawn against a *past* read, so the sync button fetches first and re-judges the snapshot it is **about to merge** (`applyRemote`, split out of `fetchNotes` for this). An unannounced conflict (`findUnacknowledgedConflicts`, keyed by slug — titles repeat) redraws and refuses to merge: merging would both overwrite an unmentioned edit *and* adopt the new `sha`, removing the 409. Likewise `checkRemoteFreshness` drops its own answer if `state.sha` moved while the GET was in flight.

**Two-tier drafts** (`src/notes-draft.js`, node-pure) — every keystroke persists the full editor state to localStorage; 5-min idle / tab hidden / manual「备份草稿」commits it to `content/notes-draft.json` on the **`notes-drafts` branch** (live data — never prune it). Publish clears both tiers.

**Auto note-art** — `.github/workflows/generate-note-art.yml` fires on `content/notes.json` pushes to main → `scripts/generate-note-art.mjs` calls the OpenAI Image API for notes without `image`, stamps the field, commits, then explicitly dispatches `deploy-pages.yml` (a GITHUB_TOKEN push cannot retrigger workflows). Prompts are text-only; reference images are never uploaded.

## Key patterns

- ES modules everywhere (`"type": "module"`)
- Procedural geometry at runtime; pre-made GLB assets are pigs (`porky-models.js`) and furniture (`furniture-models.js`). Both load through a raw `GLTFLoader` + per-URL promise cache + bbox auto-fit + procedural placeholder/fallback, and mount in R3F via `<primitive object={…}>` — **not** rewritten as JSX, **not** drei `useGLTF` (keeps the framework-agnostic core node-testable and the loader uniform across pigs/props).
- React island only on `/villa-map/` (`client:only="react"` — Three.js needs `window`); the rest of the site stays vanilla Astro static HTML.
- **Version pins (don't bump blindly):** project is on **Astro 6 / Vite 7**. Keep `@astrojs/react@^5` (the v6 line targets Astro 7 / Vite 8) and `overrides: { vite: "^7" }` in package.json. drei `<SoftShadows>` is incompatible with three r184 (broken PCSS depth shader) — avoid; shadows use `PCFShadowMap`.
- Bilingual; content defaults to Chinese (`zh`), `data-i18n` for hooks
- Tests cover HTML render, world geometry, collisions, interactions, porky / furniture / **exterior** / **architecture** placements (incl. that referenced GLB + the colormap atlas exist in `public/`), **blob shadows**, **furniture colliders**, the **beveled villa shell** (`shell.test.mjs` — node-pure build + palette), a **no-overlap regression** (`overlap.test.mjs` — solid non-chair furniture must not clip > 0.5 m²), the **mushroom interior** (`mushroom-interior.test.mjs` — zones/colliders/teleports/factory), its **round-wall containment** (`mushroom-collision.test.mjs` — player-radius-aware radial boundary across all three floors), **curved-wall decor** (`mushroom-wall-decor.test.mjs`), the **real-sky dome asset and unobstructed sightline** (`star-ceiling.test.mjs`), the **dynamic distant sky** (`mushroom-sky.test.mjs` — zero-parallax centring, reveal amount, perceptible asynchronous twinkle, L3 handoff, stencil order, reduced motion and disposal), the **two-state observatory palette/lighting rig and reachable wall switch** (`observatory-lighting.test.mjs`), the React switch state/transition (`observatory-light-switch-react.test.mjs`), and a **same-model spacing guard** (`spacing.test.mjs` — identical props ≥ 1.8 m apart on a floor; chair-family + railing exempt). `npm test` globs `tests/*.test.mjs` (one file per concern), run via the `node --test` runner.
- Impossible Observatory tests additionally cover the adaptation director, Portal/FBO geometry and lifecycle, nebula shader bounds, Gaia v1 provenance/binary/LOD/single-draw contract, automatic quality hysteresis, deterministic diagnostics, hidden R/F gating, Rift state/geometry/stencil/disposal, finite lens projection and the complete React runtime/fallback contract (`observatory-*.test.mjs`). Core and the first hidden Observatory Lab experiment are ready for human visual and target-hardware GPU acceptance.

## Impossible Observatory: runtime, quality and QA

Core implementation is complete; the remaining gate is human visual comfort/wow-factor and target-GPU performance acceptance. The detailed record is `docs/IMPOSSIBLE_OBSERVATORY_PLAN.md`.

**Render architecture:** `MushroomObservatoryRuntime` is the sole browser owner. `PlayerControls` moves the camera at R3F priority `-2`; the runtime updates one shared dark-adaptation state and renders the optional Portal at priority `-1`; R3F then renders the main scene normally. The Portal scene contains **only** the low-frequency volumetric nebula. Its FBO stores emission in RGB and accumulated dust opacity in A; a custom premultiplied-style blend draws after the fixed Gaia/hero-star field, so nearby dust can actually absorb distant starlight instead of only adding lavender glow. The 4096×1024 Milky Way backdrop, 360 procedural hero stars and Gaia Points remain in the main scene at native Canvas resolution, all clipped by the physical dome's stencil ref 7. The image brightness is 0.36 and the Gaia/hero-star additive contribution is restrained so the photograph no longer dominates. Portal targets have no depth/stencil/mipmaps and hard-cap at 1280×720. HalfFloat framebuffer failure rebuilds as RGBA8; a second FBO failure locks the session to Low. Shader failures are classified: Portal failure removes the volumetric path, Gaia failure keeps the native backdrop/hero stars, and native-sky failure fail-closes to the physical dome. WebGL context loss hides the live layers and restore rebuilds/re-prewarms them.

**Unified switch story:** `observatory-adaptation.js` emits `houseLight`, `roomDarkness`, `portalReveal`, `brightStarReveal`, `scotopicAdaptation`, `nebulaReveal`, `faintStarReveal` and `celestialMotionScale`. `Scene.jsx` lighting/palette/exposure/markers and the sky runtime all read the same `adaptationRef`; do not reintroduce independent component timers. Lights-off drops the room first, begins the Portal after 0.38 s, brings bright stars next and develops faint Gaia/nebula detail over about 10 s. Lights-on recovers in 0.65 s; leaving L3 resets the state. Once the one-shot prewarm is complete, lights-on has zero sustained cosmos draw calls. Reduced motion freezes celestial motion, not the switch fade.

**Hidden Observatory Lab v1:** while aiming through a 0.32 m camera ray at the reachable L3 wall switch, plain `R` toggles a non-Euclidean Rift and plain `F` toggles a finite-distance Gaia gravitational lens; modifier shortcuts and typing targets are ignored. R fully expands a second stencil aperture before dissolving only the L3 shell, then exposes three finite point/shard bands, three independently unfolding rings and boosted near-nebula parallax while suppressing the 4K backdrop. F applies one point-mass direction to the panorama, hero stars and Gaia, but gives the Portal dust an intentionally stronger counter-warp; its 42 m world anchor changes direction and angular size as the visitor walks. Both shortcuts silently turn lights off. E/开灯 and leaving L3 clear both requests; loss of stencil/context/native sky hard-restores the shell. Production HUD deliberately does not advertise R/F; the query-only QA panel does.

**Gaia v1:** `public/data/gaia-bright-stars-v1.bin` is a 1,920,032-byte, 80,000-row rendering subset produced by `scripts/build-gaia-star-catalog.mjs` from a reproducible Gaia DR3 `gaiadr3.gaia_source` ADQL query. `public/data/gaia-bright-stars-v1.meta.json` stores the query, SHA-256, record layout, completeness caveat and required **ESA/Gaia/DPAC** credit/acknowledgement. The shader uses `uMagnitudeLimit` against each star's Gaia G magnitude, so dark adaptation reveals bright-to-faint catalogue stars in measured order instead of fading the catalogue in as one sheet. The runtime fetches only this local static file; it never queries ESA from the visitor's browser. Keep the `-v1` filename and metadata in sync when regenerating.

| Runtime tier | Gaia | Volumetric Portal | Nebula steps | Native fallbacks |
|---|---:|---|---:|---|
| High | 80,000 | 0.68 scale, max 1280×720 | 48 | 4K backdrop + 360 hero stars |
| Medium | 35,000 | 0.55 scale, max 960×540 | 30 | 4K backdrop + 360 hero stars |
| Low | 8,000 | **disabled; no FBO allocation** | 0 | 4K backdrop + 360 hero stars |
| Minimum | 0 | **disabled; no FBO allocation** | 0 | 4K backdrop + 360 hero stars |

The quality controller uses a rolling p95: two sustained over-budget seconds downgrade one adjacent tier, eight seconds of clear headroom upgrade one tier, and a three-second cooldown prevents thrash. Capability hints cap the highest tier; Minimum is used without WebGL2 or on severely constrained devices. Gaia and Portal allocation begin only near the L2 observatory approach; the decoded 4K texture is uploaded during browser idle time. Native sky/Gaia/composite shaders are first compiled with the default framebuffer active so Three caches the real Canvas colour-space variants, then drawn to a 1×1 target to upload geometry/uniform state before reveal. Low deliberately disables the volumetric FBO; the shipped core deliberately has no Bloom and no temporal accumulation—hero-star SDF flares and an unaccumulated nebula avoid wall wash, ghosting and extra memory.

**Query-only QA harness:** ordinary `/villa-map/` visits always start with lights on and ignore quality/motion overrides. Use these only with `observatory=test` or `observatory=perf`:

- `/villa-map/?observatory=test&view=loft-center&lights=off&quality=medium&motion=full&sky=impossible` — deterministic `frameloop="never"`; panel buttons advance 0.5/2/10 s, switch `Base image`/`Impossible`, and expose `window.__villaObservatory`.
- `/villa-map/?observatory=perf&view=loft-center&lights=off&quality=medium` — real animation loop, normal `PlayerControls` walking and frame/provider snapshots.
- Views: `l2-stair`, `loft-center`, `loft-edge`, `loft-room`; qualities: `high`, `medium`, `low`, `minimum`; motion: `full`, `reduce`; sky comparison: `base`, `impossible`.

The runtime provider reports active tier/p95, adaptation channels, active sky comparison mode, Portal type/size/frame/prewarm/error, Gaia loading/LOD/count/error, 4K texture state and context-loss counters. Baseline screenshots live in `docs/observatory-baseline/`; implementation-after screenshots live in `docs/observatory-final/`.

**2026-08-02 browser QA checkpoint:** WebGL context loss/restore recovered successfully; 20 light toggles did not increase `renderer.info.memory.textures` or `.geometries`; resizing the browser to 1024×768 produced a 977×658 drawing buffer and 537×362 Medium FBO; lights-on settled at zero cosmos draws. Reduced-motion captures produced identical hashes while full-motion captures differed. The diagnostics browser observed Medium steady-state frame-time p95 around 13–16 ms and High with 80k Gaia plus a 1280×662 FBO. Hidden R/F were also verified together at Medium/35k Gaia: the Rift reached `open`, the lens reached amount 1, the HalfFloat Portal remained 960×497, room-view foreground geometry occluded the finite layers, and E/开灯 reset both with zero settled cosmos draws. These are browser-harness observations, **not** target-device GPU benchmarks. A fixed 20-second route video and three p95 runs on the target Iris Xe/M1 and UHD 620-class devices remain human acceptance evidence, not code gaps. Phase 6 head tracking, WebXR and WebGPU/TSL remain optional and unimplemented; the first manual rare-event lab is implemented.

1. ## Phase 3: grounding, solidity, outdoors

Three streams, conflict-free (each owns new files; only `Scene.jsx` + `world.js` are edited to wire them):

- **Contact shadows** (`shadows.js`) — per-piece soft **blob decals** (flat radial-gradient `PlaneGeometry` + a tiny node-safe `ShaderMaterial`, no texture/canvas), sized to the piece's `footprint`, laid at `position.y + 0.02`, rotated by `rotationY` via a wrapper group. Chosen over drei `<ContactShadows>` (one ground plane can't span two floors + async-loaded GLBs). Tunables in `shadows.js`: `SHADOW_OPACITY` 0.45, `SHADOW_PADDING` 1.35, fragment core `smoothstep(0.5, 0.22, d)` — bumped from softer defaults so the shadow reads beyond an object's base. `noShadow` pieces (rugs, tabletop items) get none.
- **Per-piece colliders** (`furniture-colliders.js`) — solid furniture/props now block the player. Rotated-AABB from `footprint`+`rotationY`, **0.85 shrink** (player radius 0.62 is added at test time, so a full box feels sticky), floor-scoped Y range. Spread into `world.colliders`. Solid set: sofas/beds/tables/bookcases/wardrobe/sideboard/lounge chairs; walk-through: rugs/lamps/books/small plants/dining+desk chairs/coat rack. NB grand-scale furniture means a big piece can fill a small room (the master bed fills the bedroom's north — you walk to its foot, not around it).
